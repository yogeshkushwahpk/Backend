# Mongoose Validation and Model Lifecycle

## Keep Invalid Data Out of the Database

---

## 1. Validate at more than one layer

Request validation checks what an API client sends. Mongoose validation protects the database even when a script, admin tool, or another service writes data.

Use both layers. Neither one replaces the other.

## 2. Built-in schema validation

```js
const productSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, 'Product name is required'],
      trim: true,
      minlength: [3, 'Product name must have at least 3 characters'],
      maxlength: [100, 'Product name cannot exceed 100 characters'],
    },
    price: {
      type: Number,
      required: true,
      min: [0, 'Price cannot be negative'],
    },
    category: {
      type: String,
      required: true,
      enum: ['books', 'electronics', 'accessories'],
    },
    sku: {
      type: String,
      required: true,
      unique: true,
      uppercase: true,
    },
  },
  { timestamps: true }
);
```

Important: `unique: true` creates a unique index; it is not a normal Mongoose validator. A duplicate value becomes a MongoDB duplicate-key error that your application must handle.

## 3. Custom validation

Use a custom validator when one field needs a business rule.

```js
const couponSchema = new mongoose.Schema({
  code: { type: String, required: true, trim: true, uppercase: true },
  percentage: {
    type: Number,
    required: true,
    validate: {
      validator: (value) => value > 0 && value <= 100,
      message: 'Percentage must be between 1 and 100',
    },
  },
});
```

For rules involving several documents, use a service function or transaction rather than trying to hide all business logic in a schema validator.

## 4. Defaults, setters, and virtuals

```js
const userSchema = new mongoose.Schema(
  {
    name: { type: String, required: true, trim: true },
    email: { type: String, required: true, lowercase: true, trim: true },
    role: { type: String, enum: ['student', 'teacher'], default: 'student' },
  },
  { timestamps: true, toJSON: { virtuals: true } }
);

userSchema.virtual('displayName').get(function displayName() {
  return `${this.name} <${this.email}>`;
});
```

A virtual is calculated when the document is used; it is not saved in MongoDB.

## 5. Middleware hooks

Mongoose middleware runs at a defined point in a document or query lifecycle.

```js
productSchema.pre('save', function setUpdatedMessage(next) {
  console.log(`Saving product: ${this.name}`);
  next();
});
```

Common uses include normalizing values, hashing a password before saving a user, and updating derived data. Keep hooks small and predictable.

`pre('save')` runs for `document.save()`. It does **not** automatically run for `findByIdAndUpdate()`. Choose the write method with this difference in mind.

## 6. Return useful validation errors

An API should return a clear `400 Bad Request` for invalid client data. Log the full original error on the server, but return only safe details to the client.

```js
if (error.name === 'ValidationError') {
  return res.status(400).json({ message: error.message });
}
```

The production API module later centralizes this code in one error handler.

## Practice

Add a `Student` model with required name and email fields, age between 16 and 100, an enum for course level, timestamps, and a lowercase email setter. Test valid data, a missing name, an invalid age, and a duplicate email.
