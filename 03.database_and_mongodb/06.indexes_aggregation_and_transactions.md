# Indexes, Aggregation, and Transactions in MongoDB

## Make Database Code Fast, Insightful, and Consistent

---

## 1. Indexes speed up known query patterns

Without an index, MongoDB may scan many documents to find a match. An index is a data structure that makes selected lookups and sorts faster, at the cost of extra storage and slower writes.

```js
productSchema.index({ category: 1, price: 1 });
```

This compound index helps queries that filter by `category` and then sort or filter by `price`.

Create indexes from real API queries. Do not index every field: each extra index makes inserts and updates more expensive.

### Useful index types

| Need | Typical index |
| --- | --- |
| Unique email or SKU | `{ email: 1 }, { unique: true }` |
| Products by category and price | `{ category: 1, price: 1 }` |
| Text search across a few fields | Text index, with careful query design |
| Records ordered by newest first | `{ createdAt: -1 }` |

Use MongoDB Compass or `explain()` to inspect whether a query uses an index.

```js
const plan = await Product.find({ category: 'books' }).explain('executionStats');
console.log(plan.executionStats.totalDocsExamined);
```

## 2. Aggregation turns documents into reports

An aggregation pipeline processes documents stage by stage. It is useful for totals, grouping, reporting, and data reshaping.

```js
const salesByCategory = await Order.aggregate([
  { $match: { status: 'paid' } },
  { $unwind: '$items' },
  {
    $group: {
      _id: '$items.category',
      orders: { $sum: 1 },
      revenue: { $sum: { $multiply: ['$items.priceAtPurchase', '$items.quantity'] } },
    },
  },
  { $sort: { revenue: -1 } },
]);
```

Common stages:

- `$match` filters early.
- `$project` selects or calculates fields.
- `$group` creates totals by a key.
- `$sort`, `$skip`, and `$limit` shape the final result.
- `$lookup` joins another collection when a report needs it.

Put `$match` near the beginning so the database processes fewer documents.

## 3. Transactions protect all-or-nothing work

Use a transaction when multiple writes must succeed together. For example, placing an order might create an order and reduce product stock. If stock cannot be reduced, the order should not be created.

```js
const session = await mongoose.startSession();

try {
  await session.withTransaction(async () => {
    const product = await Product.findById(productId).session(session);

    if (!product || product.stock < quantity) {
      throw new Error('Product is unavailable');
    }

    product.stock -= quantity;
    await product.save({ session });

    await Order.create([{ customer: userId, items: [{ product: productId, quantity }] }], {
      session,
    });
  });
} finally {
  await session.endSession();
}
```

Transactions are not needed for every write. A single-document update in MongoDB is already atomic. Use a transaction only when several documents must remain consistent together.

## 4. Production database habits

- Use a least-privilege database user, never an administrator account in the app.
- Keep connection strings in environment variables.
- Set query limits and timeouts where appropriate.
- Monitor slow queries and index usage.
- Back up production data and test restoration.
- Never expose database errors, connection strings, or stack traces to an API client.

## Practice

## What to remember

First make the data model correct. Then use indexes for measured query patterns, aggregation for reporting, and transactions only for multi-document consistency.
