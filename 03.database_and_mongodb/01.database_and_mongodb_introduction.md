# Introduction to Databases, MongoDB, and Mongoose

## 1. What is a Database?

A **database** is an organized, persistent collection of structured data stored electronically on physical disks or solid-state drives (SSDs).

### The In-Memory Problem (Why RAM is Not Enough)
In the previous module, we stored records inside JavaScript arrays (`const users = []`). 
- **Volatile Storage**: RAM memory only exists while the Node.js process is active. When the server crashes, reboots, or updates, **all data disappears permanently**.
- **Concurrency & Locking**: Managing gigabytes of records in memory leads to out-of-memory errors and race conditions.
- **Query Capabilities**: Complex filtering, indexing, transactions, and relationships cannot be efficiently computed manually in raw JavaScript arrays.

A true database provides **persistence, indexing, ACID compliance, data integrity, and high-performance querying**.

---

## 2. SQL vs. NoSQL Databases

Modern backend development uses two primary database paradigms:

| Dimension | SQL (Relational Databases) | NoSQL (Document Databases - MongoDB) |
| :--- | :--- | :--- |
| **Examples** | PostgreSQL, MySQL, SQLite, Oracle | MongoDB, CouchDB, DynamoDB |
| **Data Format** | Tables with fixed rows and columns | Collections containing flexible JSON/BSON documents |
| **Schema** | Rigid; structure must be declared via migrations before inserting data | Dynamic/Flexible; different documents in a collection can have varying fields |
| **Relationships** | Strict foreign keys and table `JOIN` operations | Embedded subdocuments or referenced ObjectIds |
| **Scaling** | Primarily Vertical (more CPU/RAM on one machine) | Horizontal Sharding (distributing data across clusters) |
| **Best For** | Banking, ERPs, accounting systems requiring complex relational transactions | Rapid application development, content platforms, real-time apps, microservices |

---

## 3. What is MongoDB?

**MongoDB** is an open-source, distributed, document-oriented NoSQL database designed for high performance, scalability, and developer productivity.

Instead of storing data in rigid tabular rows, MongoDB stores records as **BSON documents** (Binary JSON).

```json
{
  "_id": "650c8f1e2f4a1c001f8e9b21",
  "name": "Rahul Sharma",
  "email": "rahul@example.com",
  "age": 22,
  "skills": ["JavaScript", "Node.js", "Express"],
  "address": {
    "city": "Bengaluru",
    "country": "India"
  },
  "isActive": true,
  "createdAt": "2026-09-19T10:15:30.000Z"
}
```

### Key MongoDB Terminology Mapped to SQL

| SQL Concept | MongoDB Equivalent | Explanation |
| :--- | :--- | :--- |
| **Database** | **Database** | A container holding collections/tables. |
| **Table** | **Collection** | A grouping of related documents (e.g. `users`, `products`). |
| **Row** | **Document** | A single record represented as BSON key-value pairs. |
| **Column** | **Field** | A specific key inside a document (e.g. `name`, `price`). |
| **Primary Key** | **`_id` (ObjectId)** | A globally unique 12-byte identifier automatically generated by MongoDB. |

---

## 4. Understanding BSON and the `ObjectId`

### What is BSON?
BSON stands for **Binary JSON**. While JSON only natively supports `string`, `number`, `boolean`, `null`, `array`, and `object`, BSON extends JSON with additional rich data types:
- `Date` (64-bit integer timestamp)
- `Int32` and `Int64`
- `Decimal128` (high-precision floating-point numbers)
- `Binary` (storing raw images, buffers, or cryptographic hashes)
- `ObjectId`

### Anatomy of an `ObjectId`
Every document automatically receives an `_id` field of type `ObjectId` (a 24-character hexadecimal string):

$$\underbrace{\text{650c8f1e}}_{\text{4-byte timestamp}} \quad \underbrace{\text{2f4a1c}}_{\text{3-byte machine ID}} \quad \underbrace{\text{001f}}_{\text{2-byte process ID}} \quad \underbrace{\text{8e9b21}}_{\text{3-byte incrementing counter}}$$

- **Timestamp**: Encodes the exact second the document was inserted. You can extract the creation time directly from `doc._id.getTimestamp()`.
- **Globally Unique**: Highly guaranteed to be unique across machines and sharded clusters without requiring a centralized counter.

## 5. What is Mongoose? (The ODM)

While Node.js has a native MongoDB driver (`mongodb`), writing raw database queries can be error-prone and lacks schema enforcement.

**Mongoose** is an **Object Data Modeling (ODM)** library for MongoDB and Node.js. It acts as an abstraction layer providing:
1. **Schema Enforcement**: Guarantees that documents conform to expected structure and types.
2. **Built-in Validation**: Required fields, min/max numbers, email regexes, enum values.
3. **Middleware / Hooks**: Pre-save and post-save triggers (e.g. hashing passwords before saving).
4. **Convenient Query Builders**: Chainable methods like `.find().where('age').gt(18).limit(10)`.

## 6. Installation and Connection Setup

### 6.1 Install Dependencies
```bash
npm install mongoose dotenv
```

### 6.2 Connection Architecture (`config/db.js`)
Never write your database URI directly inside application code. Store it in a `.env` file!

```env
# .env
PORT=3000
MONGO_URI=mongodb://127.0.0.1:27017/my_database
# Or for MongoDB Atlas (Cloud):
# MONGO_URI=mongodb+srv://<user>:<password>@cluster0.mongodb.net/my_database?retryWrites=true&w=majority
```

Create `src/config/db.js`:
```javascript
const mongoose = require("mongoose");

const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGO_URI);
    console.log(`MongoDB Connected: ${conn.connection.host}`);
  } catch (error) {
    console.error(`MongoDB Connection Error: ${error.message}`);
    // Exit process with failure code
    process.exit(1);
  }
};

module.exports = connectDB;
```

## 7. Schemas and Models in Mongoose

### 7.1 Defining a Schema
A **Schema** defines the blueprint (fields, types, default values, validators) for documents in a collection.

```javascript
const mongoose = require("mongoose");

const userSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, "Name is required"],
      trim: true,
      minlength: [2, "Name must be at least 2 characters"]
    },
    email: {
      type: String,
      required: [true, "Email is required"],
      unique: true, // Creates a unique index in MongoDB
      lowercase: true,
      trim: true
    },
    age: {
      type: Number,
      min: [18, "Must be at least 18 years old"],
      max: [100, "Maximum age is 100"]
    },
    role: {
      type: String,
      enum: ["student", "mentor", "admin"],
      default: "student"
    },
    isActive: {
      type: Boolean,
      default: true
    }
  },
  {
    timestamps: true // Automatically adds `createdAt` and `updatedAt` fields
  }
);
```

### 7.2 Creating a Model
A **Model** is a compiled constructor derived from the schema. Instances of Models represent documents that can be saved and retrieved from the database.

```javascript
const User = mongoose.model("User", userSchema);

module.exports = User;
```

> [!TIP]
> **Collection Naming Convention**: Mongoose automatically looks for the plural, lowercased version of your model name. 
> Thus, `mongoose.model("User", ...)` will read and write to the collection named **`users`** in MongoDB.

## 8. Core CRUD Operations with Mongoose

### 8.1 Create (Insert)
```javascript
// Method 1: Instantiate & Save
const newUser = new User({ name: "Rahul", email: "rahul@test.com", age: 22 });
await newUser.save();

// Method 2: Shorthand Model.create()
const createdUser = await User.create({
  name: "Pooja",
  email: "pooja@test.com",
  age: 24
});
```

---

### 8.2 Read (Query)
```javascript
// 1. Fetch all documents
const allUsers = await User.find();

// 2. Fetch with filter criteria
const activeStudents = await User.find({ role: "student", isActive: true });

// 3. Fetch single document by unique field
const user = await User.findOne({ email: "rahul@test.com" });

// 4. Fetch by MongoDB _id
const userById = await User.findById("650c8f1e2f4a1c001f8e9b21");
```

---

### 8.3 Update (Modify)
```javascript
// Recommended: findByIdAndUpdate
const updatedUser = await User.findByIdAndUpdate(
  "650c8f1e2f4a1c001f8e9b21",
  { age: 23, role: "mentor" },
  {
    new: true,           // Returns the modified document rather than original
    runValidators: true  // Enforces schema rules (e.g. min age, enum) during update
  }
);
```

---

### 8.4 Delete (Remove)
```javascript
const deletedUser = await User.findByIdAndDelete("650c8f1e2f4a1c001f8e9b21");

if (!deletedUser) {
  console.log("No user found with that ID");
}
```

## 9. Common Beginner Mistakes

| Mistake | Why it happens | How to fix |
| :--- | :--- | :--- |
| **Missing `await` on Mongoose calls** | Mongoose methods return Promises/Thenables. Without `await`, you receive a Query object instead of data. | Always use `await User.find()` inside an `async` function. |
| **Omitting `{ new: true }` in updates** | By default, `findByIdAndUpdate` returns the document *before* the update occurred. | Pass `{ new: true, runValidators: true }` as the 3rd argument. |
| **Hardcoding MongoDB URI in Git** | Exposes database passwords and allows unauthorized cluster access. | Always place credentials in `.env` and add `.env` to `.gitignore`. |
| **Passing invalid hex strings to `findById`** | Mongoose throws a `CastError` if ID length or format is invalid. | Validate ID format using `mongoose.Types.ObjectId.isValid(id)` or handle errors in `catch`. |
| **Forgetting `unique: true` creates an index** | Mongoose creates unique indexes on server start. If duplicates already exist in DB, the index will fail to build silently. | Clear duplicate records before applying unique constraint. |

## 12. Interview Questions & Model Answers

### Q1: Why do we use Mongoose when MongoDB is schema-less?
**Answer:**
While MongoDB's schema-less nature offers flexibility at the database storage layer, real-world backend applications require predictable data structures, business validations, and type safety. Without an ODM like Mongoose, validation logic must be manually repeated across every route handler. Mongoose enforces schemas at the application layer, preventing corrupted or incomplete records from being stored, while offering features like middleware, population (simulated joins), and schema getters/setters.

### Q2: What happens if `await mongoose.connect()` fails when the server boots?
**Answer:**
If the database connection fails, subsequent database queries across all route controllers will time out or throw unhandled exceptions. Best architectural practice dictates catching the connection error in `config/db.js` and invoking `process.exit(1)`. This immediately terminates the Node.js process so that process managers (like Docker, Kubernetes, or PM2) can detect the startup failure and trigger appropriate restart or alert policies.
