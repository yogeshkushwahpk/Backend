# Mongoose CRUD and Query Patterns

## Read and Change MongoDB Data Safely

---

Assume this lesson uses a `Product` model with `name`, `price`, `category`, and `inStock` fields.

## 1. Create documents

```js
const product = await Product.create({
  name: 'Mechanical Keyboard',
  price: 89.99,
  category: 'accessories',
});
```

`create()` validates the document, saves it, and returns the created document. In a real controller, wrap it in `try`/`catch` or pass the error to the central Express error handler you will learn later.

## 2. Find one document

```js
const product = await Product.findById(productId);

if (!product) {
  throw new Error('Product not found');
}
```

Use `findById()` when the client sends an `_id`. Use `findOne()` for another unique condition.

```js
const product = await Product.findOne({ name: 'Mechanical Keyboard' });
```

## 3. Filter, select, sort, and limit

Never return an unlimited collection in a production API.

```js
const products = await Product.find({
  category: 'accessories',
  inStock: true,
  price: { $lte: 100 },
})
  .select('name price category')
  .sort({ price: 1 })
  .limit(20)
  .lean();
```

`select()` removes fields the client does not need. `lean()` returns plain JavaScript objects for read-only queries and avoids Mongoose document overhead.

## 4. Pagination

Use a page size and a page number for a beginner-friendly list API.

```js
const page = Math.max(Number(req.query.page) || 1, 1);
const limit = Math.min(Number(req.query.limit) || 20, 100);
const skip = (page - 1) * limit;

const [products, total] = await Promise.all([
  Product.find({ inStock: true }).sort({ createdAt: -1 }).skip(skip).limit(limit).lean(),
  Product.countDocuments({ inStock: true }),
]);

res.json({
  data: products,
  pagination: { page, limit, total, pages: Math.ceil(total / limit) },
});
```

Later, high-volume lists may use cursor pagination. Learn page/limit first because it is easy to reason about.

## 5. Update documents

```js
const updatedProduct = await Product.findByIdAndUpdate(
  productId,
  { price: 79.99 },
  { new: true, runValidators: true }
);
```

`new: true` returns the changed document. `runValidators: true` is important because update queries do not run schema validation by default.

For multi-step domain logic, load the document, change it, then save it.

```js
const product = await Product.findById(productId);
if (!product) throw new Error('Product not found');

product.inStock = false;
await product.save();
```

This approach runs document middleware such as `pre('save')` hooks.

## 6. Delete documents carefully

```js
const deletedProduct = await Product.findByIdAndDelete(productId);

if (!deletedProduct) {
  throw new Error('Product not found');
}
```

For records that must be retained for audit purposes, use a soft delete such as `isDeleted: true` instead of permanently deleting the document.

## 7. Query operators you will use often

| Need | MongoDB operator |
| --- | --- |
| Equal to one value | `{ category: 'books' }` |
| Greater / less than | `{ price: { $gte: 10, $lte: 50 } }` |
| Match one of several values | `{ category: { $in: ['books', 'games'] } }` |
| Field exists | `{ discount: { $exists: true } }` |
| Combine conditions | `{ $or: [{ inStock: true }, { featured: true }] }` |

Do not pass arbitrary client input directly into a MongoDB query. Build an allowlist of accepted filters and convert their values deliberately.
