# Node.js Error Handling and Debugging

## Find Problems Early and Fail Safely

---

## 1. Errors are normal

An error is information that tells us a program could not complete an operation. Examples include a missing file, an invalid JSON file, a busy port, or a rejected database query.

The goal is not to hide errors. The goal is to handle expected errors clearly and make unexpected errors easy to investigate.

## 2. Throwing and catching synchronous errors

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error('A number cannot be divided by zero.');
  }

  return a / b;
}

try {
  console.log(divide(10, 0));
} catch (error) {
  console.error(error.message);
}
```

Use `throw` when a function cannot produce a valid result. Catch an error only where you can add useful context, recover, or end the operation safely.

## 3. Handling asynchronous errors

Use `try`/`catch` with `await`.

```js
const fs = require('fs/promises');

async function loadSettings() {
  try {
    const text = await fs.readFile('settings.json', 'utf8');
    return JSON.parse(text);
  } catch (error) {
    console.error('Could not load settings:', error.message);
    return null;
  }
}
```

For callback APIs, inspect the error-first callback argument. For Promise chains, finish the chain with `.catch()`.

## 4. Read an error message and stack trace

```js
try {
  JSON.parse('{ invalid json }');
} catch (error) {
  console.error(error.name);    // SyntaxError
  console.error(error.message); // explanation
  console.error(error.stack);   // file and line history
}
```

The stack trace is useful during development. Do not send a stack trace to an API client in production; it can expose implementation details.

## 5. Create meaningful application errors

```js
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
  }
}

throw new AppError('User was not found.', 404);
```

The Express module will later apply this same idea to HTTP responses. For now, practice making error messages specific and actionable.

## 6. Debug with small tools first

Use these steps in order:

1. Reproduce the issue with the smallest input.
2. Read the first relevant error message and line number.
3. Log the value and its type near the failing code.
4. Check asynchronous code has `await` and error handling.
5. Fix the cause, then remove temporary logs.

Run Node’s built-in inspector when logs are not enough:

```bash
node --inspect-brk index.js
```

Then open Chrome DevTools at `chrome://inspect` or attach your editor’s debugger. `--inspect-brk` pauses before the first line so you can add breakpoints.

## 7. Last-resort process handlers

These handlers are useful for logging fatal failures, not for making a broken process healthy again.

```js
process.on('unhandledRejection', (reason) => {
  console.error('Unhandled rejection:', reason);
  process.exit(1);
});

process.on('uncaughtException', (error) => {
  console.error('Uncaught exception:', error);
  process.exit(1);
});
```

In a production application, a process manager or hosting platform should restart a process that exits unexpectedly.

## Practice

Write a script that reads JSON from a file. Test three cases: a valid file, a missing file, and invalid JSON. Make sure each failure produces a helpful message without a confusing crash.

## What to remember

Use `try`/`catch` with `await`, keep error messages useful, and use the stack trace to find the source line. Do not add framework-specific HTTP error handling to a Node-only script.
