# Asynchronous JavaScript and the Event Loop

## Write Node.js Code That Does Not Block the Server

---

## Why this lesson comes before a server

A backend server must be able to start one task, wait for slow work such as a file read or database request, and still accept another request. This is the idea behind asynchronous JavaScript.

You should understand this lesson before creating an HTTP server. You do not need to memorize the internal event-loop phases.

---

## 1. Synchronous vs asynchronous code

Synchronous code finishes one line before the next line can run.

```js
console.log('first');
console.log('second');
```

Asynchronous code starts work that finishes later. Node can continue running other code while it waits.

```js
console.log('first');

setTimeout(() => {
  console.log('this runs later');
}, 1000);

console.log('second');
```

The output is `first`, `second`, then `this runs later`.

## 2. Callbacks: the original Node style

A callback is a function that Node calls when an asynchronous task finishes.

```js
const fs = require('fs');

fs.readFile('message.txt', 'utf8', (error, text) => {
  if (error) {
    console.error(error.message);
    return;
  }

  console.log(text);
});

console.log('Node is reading the file...');
```

The first callback argument is usually an error. Always handle it before using the result.

## 3. Promises

A Promise represents a value that will be available later. It can be pending, fulfilled, or rejected.

```js
function getGreeting() {
  return Promise.resolve('Hello from Node');
}

getGreeting()
  .then((message) => console.log(message))
  .catch((error) => console.error(error));
```

Many modern Node APIs offer Promise versions. For example, `fs/promises` lets us read files without nesting callbacks.

```js
const fs = require('fs/promises');

fs.readFile('message.txt', 'utf8')
  .then((text) => console.log(text))
  .catch((error) => console.error(error.message));
```

## 4. `async` and `await`

`async`/`await` is the clearest way to work with Promises in backend code. `await` pauses only the current `async` function; it does not freeze the whole Node process.

```js
const fs = require('fs/promises');

async function showMessage() {
  try {
    const text = await fs.readFile('message.txt', 'utf8');
    console.log(text);
  } catch (error) {
    console.error('Could not read the file:', error.message);
  }
}

showMessage();
```

Use `try`/`catch` around awaited work. A rejected Promise is not handled by a normal `try`/`catch` unless you use `await` inside that block.

## 5. A simple event-loop model

Use this mental model:

1. JavaScript runs on the call stack.
2. Slow I/O work is handed to Node or the operating system.
3. When that work finishes, its callback or Promise continuation waits in a queue.
4. When the call stack is free, Node runs the waiting continuation.

This is why the server can handle many waiting operations. It does **not** make CPU-heavy JavaScript fast. A long loop still blocks the call stack.

```js
// Avoid CPU-heavy work like this inside a request handler.
for (let i = 0; i < 10_000_000_000; i += 1) {
  // blocks the event loop
}
```

## 6. Which style should you use?

| Situation | Preferred style |
| --- | --- |
| Reading modern backend code | `async`/`await` |
| Using an older Node API | Error-first callback |
| Handling a value in a chain | `.then()` / `.catch()` |
| CPU-intensive work | Move it to a worker, queue, or separate service later |

## 7. Common mistakes

- Forgetting `await` and accidentally sending a Promise instead of data.
- Using `readFileSync` inside a request handler.
- Ignoring a rejected Promise.
- Assuming `setTimeout(fn, 0)` runs immediately.
- Putting expensive loops inside the server’s request path.

## Practice

Create `notes.txt`, then write a small script that reads it with `fs/promises` and prints its contents. Next, deliberately use a missing filename and verify that your `catch` block runs.

## What to remember

Node is excellent at waiting for I/O without blocking other requests. In this course, use `async`/`await` with `try`/`catch` as the default style.
