# The Node.js Process, Environment Variables, and Configuration

## Give a Backend Application Safe, Predictable Runtime Settings

---

## 1. What is `process`?

When you run `node index.js`, the operating system starts a Node process. Node exposes information about that running program through the global `process` object.

```js
console.log(process.version); // installed Node.js version
console.log(process.cwd());   // directory where the command was run
console.log(process.argv);    // command-line arguments
```

Do not use `process.exit()` as normal control flow. It immediately stops the program. Use it only when the application cannot safely start or must shut down.

## 2. Command-line arguments

Arguments let one script behave differently without changing source code.

```js
// node greet.js Yogesh
const name = process.argv[2] || 'student';
console.log(`Hello, ${name}!`);
```

The first two values are the Node executable and the script path, so user arguments begin at `process.argv[2]`.

## 3. Environment variables

Environment variables hold settings that change between machines or deployments:

- `PORT`
- database connection string
- JWT secret
- application environment (`development`, `test`, or `production`)

Never put passwords, API keys, or connection strings directly in Git-tracked source code.

```js
const port = Number(process.env.PORT) || 3000;
const environment = process.env.NODE_ENV || 'development';

console.log({ port, environment });
```

Every value in `process.env` is a string. Convert values deliberately with `Number`, `Boolean` logic, or validation.

## 4. Loading a local `.env` file

For local development, use `dotenv`.

```bash
npm install dotenv
```

Create a `.env` file:

```env
PORT=3000
NODE_ENV=development
MONGO_URI=mongodb://127.0.0.1:27017/course_db
```

Load it as the first line of your application entry file:

```js
require('dotenv').config();
```

Add `.env` to `.gitignore`. Commit a `.env.example` file with placeholder values instead.

## 5. Validate required configuration at startup

Fail early with a useful message rather than letting a request fail later.

```js
function getRequiredEnv(name) {
  const value = process.env[name];

  if (!value) {
    throw new Error(`Missing required environment variable: ${name}`);
  }

  return value;
}

const config = {
  port: Number(process.env.PORT) || 3000,
  mongoUri: getRequiredEnv('MONGO_URI'),
};
```

## 6. Build file paths safely

Do not join file paths with string concatenation. Different operating systems use different separators.

```js
const path = require('path');

const uploadsDirectory = path.join(__dirname, 'uploads');
const filePath = path.join(uploadsDirectory, 'profile.png');
```

`__dirname` is the directory of the current CommonJS file. `process.cwd()` is the directory where the user ran the command; these can be different.

## 7. Graceful shutdown

When a development server is stopped with `Ctrl + C`, it receives `SIGINT`. In production, a platform often sends `SIGTERM`. Close open resources before ending the process.

```js
process.on('SIGINT', async () => {
  console.log('Stopping server...');
  // await databaseConnection.close();
  process.exit(0);
});
```

You will apply this after learning databases. For now, remember that a server should close cleanly rather than abandon active resources.

## Checklist

- Keep configuration outside source code.
- Never commit `.env`.
- Validate important settings when the app starts.
- Treat every environment-variable value as a string.
- Use `path.join()` for filesystem paths.
