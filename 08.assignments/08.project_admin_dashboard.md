# Project: JWT-Protected Admin Dashboard

## Academic session 24

Complete authentication, JWT, EJS, and static-files lessons before this project.

## Goal

Build a small admin dashboard that shows protected information only after a user logs in and sends a valid JWT.

## Required flow

1. A user logs in through the existing `POST /login` route.
2. The route returns a JWT.
3. The dashboard frontend sends `Authorization: Bearer <token>` to a protected API route.
4. The JWT middleware verifies the token.
5. The API returns dashboard data only to an authenticated user.

```js
app.get('/api/admin/stats', authMiddleware, (req, res) => {
  res.json({
    welcome: req.user.email,
    totals: { users: 24, posts: 12, messages: 8 },
  });
});
```

Render the dashboard shell with EJS:

```js
app.get('/admin', (req, res) => {
  res.render('admin-dashboard', { title: 'Admin Dashboard' });
});
```

The browser-side JavaScript should call `/api/admin/stats` with the token and render the returned values. For classroom practice, a token can be pasted into a form or stored temporarily in browser storage. Explain in the README that production applications need stronger token-storage and XSS protection decisions.

## Requirements

- Login route returns a JWT.
- Protected API route returns `401` with no token and `403` for an invalid token.
- Dashboard shows the logged-in user and at least three statistics.
- Logout clears the locally stored token.
- Use the authentication module’s password hashing; never store a plain password.
- Document test steps in Postman and in the browser.

## Extension

Add a `role` field to the User model and restrict `/api/admin/stats` to `admin` users. Return `403` for an authenticated non-admin user.
