# Request Validation with Express-Validator

## 1. What Is Request Validation?

**Request Validation** is the process of verifying that incoming client payloads (`req.body`, `req.params`, `req.query`) conform to expected data types, formats, length constraints, and business rules **before** being processed by controllers or saved to the database.

Without validation, invalid or hostile data can enter the system:
- Users registering with empty strings as usernames
- Broken email addresses like `"notanemail"`
- Single-digit passwords like `"1"`
- Negative prices or quantities in e-commerce orders

---

## 2. Why Do We Need Dedicated Request Validation?

While Mongoose schemas provide database-level validation, relying solely on Mongoose for validation has significant drawbacks:
1. **Late Execution**: The request must travel all the way through route handlers, database drivers, and connection pools before being rejected.
2. **Ugly Error Messages**: Mongoose validation errors format raw BSON exceptions rather than clean, client-friendly error objects.
3. **Non-Database Routes**: Endpoints like `/api/contact`, `/api/login`, or third-party webhooks don't write directly to MongoDB and thus have no Mongoose schema.
4. **Sanitization**: `express-validator` allows trimming strings, normalizing emails to lowercase, and sanitizing inputs to prevent XSS.

---

## 3. Real-World Analogy

Imagine a **Border Immigration Checkpoint**:
- Before boarding an international flight, immigration checks your passport, visa, and ticket validity.
- If your passport is expired, you are turned away immediately at the gate (**Validation Layer**).
- The pilot and flight attendants (**Controllers & Database**) never have to waste fuel or deal with passengers who should not have boarded.

## 4. What is `express-validator`?

`express-validator` is an Express middleware library that wraps the battle-tested `validator.js` suite.

### Installation
```bash
npm install express-validator
```

### The Two Core Functions
```javascript
const { body, validationResult } = require("express-validator");
```

| Import | Purpose |
| :--- | :--- |
| **`body()`** | Chains validation and sanitization rules for fields in `req.body`. |
| **`validationResult()`** | Gathers all validation errors generated by the rules on the current request. |

---

## 5. The 3-Stage Validation Pipeline

```
[Incoming HTTP Request]
         │
         ▼
[Stage 1: Validation Rules Run]
body("email").isEmail(), body("password").isLength({ min: 6 })
         │
         ▼
[Stage 2: Validation Middleware]
const errors = validationResult(req);
if (!errors.isEmpty()) -> Return 400 Bad Request with formatted error array
         │ (Zero errors found)
         ▼
[Stage 3: Controller Function Runs]
User.create(req.body)
```

## 6. Validator Cheat Sheet

| Method | What It Verifies | Code Example |
| :--- | :--- | :--- |
| `.notEmpty()` | Field cannot be null, undefined, or `""` | `body("name").notEmpty()` |
| `.isEmail()` | Must match valid RFC 5322 email syntax | `body("email").isEmail()` |
| `.isLength({ min, max })` | String length between bounds | `body("password").isLength({ min: 8 })` |
| `.isNumeric()` | Value consists of numeric digits | `body("phone").isNumeric()` |
| `.isInt({ min, max })` | Value is an integer within range | `body("age").isInt({ min: 18, max: 100 })` |
| `.isFloat({ min })` | Value is a decimal number | `body("price").isFloat({ min: 0.01 })` |
| `.isURL()` | Value is a valid HTTP/HTTPS URL | `body("website").isURL()` |
| `.isIn([...])` | Value is a member of an allowed list | `body("role").isIn(["admin", "user"])` |
| `.optional()` | Field is optional; only validates if present | `body("bio").optional().isLength({ max: 200 })` |
| `.trim()` | Sanitizer: removes whitespace from ends | `body("name").trim().notEmpty()` |

### Custom Error Messages with `.withMessage()`
```javascript
body("email")
  .notEmpty().withMessage("Email is required")
  .isEmail().withMessage("Please enter a valid email address");
```

## 7. Production Implementation in MVC

### Step 1: Reusable Validation Middleware (`src/middlewares/validate.js`)

```javascript
const { body, validationResult } = require("express-validator");

// 1. Array of validation rules for Registration
const registerValidationRules = [
  body("name")
    .trim()
    .notEmpty().withMessage("Name is required")
    .isLength({ min: 2 }).withMessage("Name must be at least 2 characters long"),

  body("email")
    .trim()
    .notEmpty().withMessage("Email is required")
    .isEmail().withMessage("Please provide a valid email address")
    .normalizeEmail(),

  body("password")
    .notEmpty().withMessage("Password is required")
    .isLength({ min: 6 }).withMessage("Password must be at least 6 characters long"),

  body("age")
    .optional()
    .isInt({ min: 1, max: 120 }).withMessage("Age must be a valid integer between 1 and 120")
];

// 2. Middleware that inspects validationResult
const validate = (req, res, next) => {
  const errors = validationResult(req);

  if (!errors.isEmpty()) {
    // Format error array cleanly for clients
    const formattedErrors = errors.array().map(err => ({
      field: err.path,
      message: err.msg
    }));

    return res.status(400).json({
      success: false,
      message: "Validation failed",
      errors: formattedErrors
    });
  }

  next();
};

module.exports = { registerValidationRules, validate };
```

---

### Step 2: Controller (`src/controllers/user.controller.js`)

Notice how clean the controller is. It does not need repetitive `if (!email)` statements:

```javascript
const User = require("../models/user.model");

const registerUser = async (req, res) => {
  try {
    const { name, email, password, age } = req.body;

    const existingUser = await User.findOne({ email });
    if (existingUser) {
      return res.status(400).json({
        success: false,
        message: "A user with this email already exists"
      });
    }

    const newUser = await User.create({ name, email, password, age });

    res.status(201).json({
      success: true,
      message: "User registered successfully",
      data: {
        id: newUser._id,
        name: newUser.name,
        email: newUser.email
      }
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error during registration",
      error: error.message
    });
  }
};

module.exports = { registerUser };
```

---

### Step 3: Route Chaining (`src/routes/user.routes.js`)

```javascript
const express = require("express");
const router = express.Router();

const { registerUser } = require("../controllers/user.controller");
const { registerValidationRules, validate } = require("../middlewares/validate");

// Pipeline: Rules -> Checker Middleware -> Controller Handler
router.post("/register", registerValidationRules, validate, registerUser);

module.exports = router;
```

## 9. Common Mistakes to Avoid

| Mistake | Consequence | Correct Approach |
| :--- | :--- | :--- |
| **Forgetting to call `next()` in `validate`** | The request hangs indefinitely when validation succeeds. | Always call `next()` after checking `errors.isEmpty()`. |
| **Validating optional fields without `.optional()`** | Omitting an optional profile bio triggers a validation failure. | Prefix optional rules with `.optional()`. |
| **Writing validation rules directly in route files** | Clutters routing logic and duplicates rules across handlers. | Place validation arrays in a dedicated `middlewares/validation/` folder. |
| **Using `res.status(500)` for validation errors** | Confuses clients into thinking the server crashed. | Use `400 Bad Request` for all validation rejections. |

## 12. Interview Questions & Model Answers

### Q1: Why should backend applications validate inputs even if the frontend already validates them?
**Answer:**
Frontend validation exists solely for user experience (giving immediate visual feedback in forms). However, **clients can be bypassed effortlessly**. Attackers do not need to use your web form; they can send raw HTTP requests directly using Postman, `curl`, Python scripts, or modified browser developer consoles. The backend is the ultimate gatekeeper of the database. If the backend does not enforce strict validation, malicious or malformed payloads will corrupt data storage and compromise system security.

### Q2: What is the difference between `param()`, `query()`, and `body()` in `express-validator`?
**Answer:**
- **`body("field")`**: Targets data submitted in the HTTP request payload (`req.body`, typically JSON or URL-encoded).
- **`param("id")`**: Targets dynamic route parameters declared in the URL path (`req.params`, e.g. `/users/:id`).
- **`query("search")`**: Targets query string key-value pairs appended after the `?` symbol in the URL (`req.query`, e.g. `/users?role=admin`).
