# Introduction to Express.js

## From Raw HTTP to Clean, Scalable APIs

---

## 1. Why Express.js Exists

In the previous chapters, you learned how to create a web server using Node’s native `http` module. While building servers with raw HTTP is essential for understanding how the web works, you also experienced the friction:
* Manual routing requires messy `if / else if / else` or `switch` statements.
* Collecting POST bodies requires listening to `'data'` and `'end'` stream events.
* Parsing JSON requires manual `JSON.parse(body)`.
* Writing headers and status codes is repetitive.
* Supporting dynamic parameters like `/users/:id` requires complex regular expressions.

**Express.js exists to solve all of these problems without changing the underlying fundamentals.**

---

## 2. What is Express.js?

**Express.js is a minimal, fast, and unopinionated web application framework for Node.js.**

Key principles:
* Built directly **on top of the Node.js `http` module**.
* Does **not replace Node.js**; it runs on top of it to improve developer experience.
* Does **not change how HTTP works**; it simply abstracts the repetitive boilerplate.
* Provides a powerful **routing system** and an extensible **middleware architecture**.

```
┌────────────────────────────────────────────────────────┐
│                   Your Application                     │
├────────────────────────────────────────────────────────┤
│                      Express.js                        │
│   (Routing, Helpers, Middleware Pipeline, res.json)   │
├────────────────────────────────────────────────────────┤
│                 Node.js Core (http, fs)                │
├────────────────────────────────────────────────────────┤
│                   V8 Engine & libuv                    │
└────────────────────────────────────────────────────────┘
```

---

## 3. Express vs Raw HTTP Module: Side-by-Side Comparison

| Architectural Aspect | Node.js `http` Module | Express.js Framework |
| :--- | :--- | :--- |
| **Server Creation** | `http.createServer((req, res) => ...)` | `const app = express()` |
| **Routing** | Clunky `if (req.url === '/users' && req.method === 'GET')` | Elegant `app.get('/users', handler)` |
| **Request Body Parsing** | Manual stream assembly (`req.on('data')`) | One-line middleware (`app.use(express.json())`) |
| **Dynamic Parameters** | Requires manual string splitting or Regex | Built-in `:id` accessible via `req.params.id` |
| **Sending JSON Responses** | `res.writeHead(200, ...)` + `res.end(JSON.stringify(data))` | `res.status(200).json(data)` |
| **Pipeline Architecture** | Single monolithic callback | Modular **Middleware Chain** |

Express improves **developer speed, readability, and maintainability** while running on the exact same V8 engine and libuv event loop.

## 4. Creating a Basic Express Server

### Step 1: Install Express
```bash
npm install express
```

### Step 2: Write `index.js`
```js
const express = require("express");

// Initialize Express application
const app = express();

// Middleware to parse incoming JSON bodies automatically
app.use(express.json());

// Define a basic GET route
app.get("/", (req, res) => {
  res.send("Express server is up and running smoothly!");
});

// Define a JSON API route
app.get("/api/health", (req, res) => {
  res.status(200).json({
    status: "healthy",
    uptime: process.uptime(),
    timestamp: new Date().toISOString()
  });
});

// Start listening for traffic
const PORT = 3000;
app.listen(PORT, () => {
  console.log(`Server listening on http://localhost:${PORT}`);
});
```

## 5. The Express Request–Response Lifecycle

![Express Request Response Cycle](https://media.geeksforgeeks.org/wp-content/uploads/20250705152348042640/Request-and-Response-Cycle.webp)

![Express Lifecycle Pipeline](https://miro.medium.com/1%2AkMNzu4zx40QvwQUWa9dCOw.png)

When an HTTP request enters an Express application:
1. **Entry Point:** The request arrives at the server.
2. **Middleware Pipeline:** The request flows sequentially through any registered middleware functions (`app.use(...)`).
3. **Route Matcher:** Express matches the request method (GET/POST/etc.) and URL path against registered routes.
4. **Controller Handler:** The matching route callback executes business logic.
5. **Response Return:** The response is sent back to the client (`res.json()`), concluding the cycle.

---

## 6. Enriched `req` and `res` Objects in Express

Express wraps the native Node.js `req` and `res` objects, adding convenient helper properties and methods:

### The Request (`req`) Helpers:
* **`req.params`**: Object containing route parameters defined with colons (e.g. `/users/:id` → `req.params.id`).
* **`req.query`**: Object containing parsed URL query strings (e.g. `/products?category=shoes` → `req.query.category`).
* **`req.body`**: Object containing parsed request body (available when `express.json()` middleware is used).
* **`req.headers`**: Access incoming request headers.
* **`req.ip`**: The client’s remote IP address.

### The Response (`res`) Helpers:
* **`res.status(code)`**: Sets the HTTP status code (e.g. `res.status(404)`). Chainable!
* **`res.json(data)`**: Automatically sets `Content-Type: application/json`, stringifies the JavaScript object, and ends the response.
* **`res.send(body)`**: Generic response method that accepts strings, HTML, buffers, or objects.
* **`res.sendStatus(code)`**: Sets the status code and sends its standard status text as the body (e.g. `res.sendStatus(403)` sends `"Forbidden"`).

```js
// Chaining status and JSON response:
res.status(201).json({
  success: true,
  message: "Product created successfully",
  data: newProduct
});
```

## 7. Built-in Middleware: `express.json()`

![Express Middleware Diagram](https://developer.okta.com/assets-jekyll/blog/express-middleware-examples/middleware-30b3b30ad54e21d8281719042860f3edd9fb1f40f93150233a08165d908f4631.png)

![Express Middleware Pipeline](https://cdn.hashnode.com/res/hashnode/image/upload/v1669745982483/k3wiCbsHY.png)

In raw HTTP, you had to write 10 lines of buffer aggregation to parse a JSON body.
In Express, you write **one line**:

```js
app.use(express.json());
```

### What `express.json()` does under the hood:
1. Intercepts incoming requests whose `Content-Type` is `application/json`.
2. Listens to the incoming data stream chunks.
3. Parses the chunks into a JavaScript object.
4. Attaches the parsed object directly to `req.body`.
5. Calls `next()` so your route handler can simply read `req.body.name`.

> **Rule:** Always place `app.use(express.json())` at the top of your file **before** your route definitions.

---

## 8. What Express Does NOT Do

It is equally important to understand the boundaries of Express:
* Express does **not connect to databases** automatically. You choose and configure your database driver (e.g. Mongoose, Prisma, pg).
* Express does **not manage user sessions or authentication** out of the box. You implement auth using libraries like `bcrypt` and `jsonwebtoken`.
* Express does **not make your code multi-threaded**. The single-threaded non-blocking nature of Node.js still applies. Synchronous CPU-blocking loops will still freeze an Express server.

---

## 9. Common Beginner Mistakes

1. **Forgetting `app.use(express.json())`:**
   * Results in `req.body` being `undefined` inside POST and PUT route handlers.
2. **Placing Middleware After Routes:**
   * Express executes middleware in top-to-bottom order. If `express.json()` is placed below `app.post(...)`, the route executes before the body is parsed!
3. **Using `res.json()` twice in the same handler:**
   * Throws `Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client`. Always use `return res.status(...).json(...)` if you exit early.

---

## 10. Summary & Key Takeaways

* Express is a fast, unopinionated framework running on top of Node’s `http` module.
* It abstracts routing, request parsing, and response formatting into clean, declarative APIs.
* Express enriches `req` with `req.params`, `req.query`, and `req.body`.
* `res.status().json()` is the standard pattern for returning API responses.
* Middleware functions execute sequentially in the order they are registered.

## 11. Interview Questions

**Q1: What does it mean that Express is an "unopinionated" framework?**
*Answer:* An "opinionated" framework (like Ruby on Rails or NestJS) enforces a rigid file structure, naming conventions, and built-in ORMs. Express is "unopinionated" because it provides complete freedom: you choose how to organize folders, which database libraries to use, how to handle validation, and how to structure architecture.

**Q2: What is the purpose of `express.urlencoded({ extended: true })`?**
*Answer:* It is a built-in middleware that parses incoming requests with URL-encoded payloads (typically submitted from traditional HTML `<form>` tags). The `extended: true` option allows parsing rich objects and arrays using the `qs` library.

**Q3: How does Express route matching work?**
*Answer:* Express evaluates routes in the exact order they are declared in code, from top to bottom. It compares the incoming HTTP method and URL pathname against registered route patterns. When the first match is found, its handler callback executes.
