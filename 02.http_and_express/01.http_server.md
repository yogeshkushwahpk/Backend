# Creating a Server Using the HTTP Module

## Understanding How Backend Web Servers Actually Work

---

## 1. What is a Web Server?

At its core, a **web server** is a long-running program that:
1. Binds to a specific network **port** (e.g. 3000, 8080)
2. Continuously listens for incoming network connections
3. Parses incoming HTTP requests sent by clients (browsers, mobile apps, Postman)
4. Executes application logic
5. Returns a structured HTTP response back to the client

In Node.js, this fundamental networking capability is provided by the built-in **`http` core module**.

---

## 2. Why Start with the Raw `http` Module?

Modern Node.js applications almost universally use frameworks like **Express.js**. However, frameworks can feel like "magic" if you don't understand the underlying primitives:
* Express does not invent its own HTTP protocol; it is built **directly on top of Node's `http` module**.
* In Express, `req` and `res` are simply enriched versions of the native Node.js `http.IncomingMessage` and `http.ServerResponse` objects.
* Starting with raw HTTP ensures you understand what headers are, why `res.end()` is required, and how Node handles high concurrency without multi-threading.

---

## 3. Real-World Analogy: The Postal Mailroom

Think of an HTTP server like a corporate mailroom:
* **The Server (`http.createServer`):** The mailroom staff.
* **The Port (`3000`):** The mailroom's office door number in the building.
* **The Request (`req`):** An incoming sealed envelope from a customer containing their letter (URL path, query parameters) and their return address (IP, headers).
* **The Response (`res`):** The outgoing reply envelope stamped and mailed back by the mailroom staff.
* **Ending the Response (`res.end`):** Dropping the envelope into the mailbox. If the staff forgets to seal and mail it, the customer waits by their mailbox forever.

## 4. Creating a Minimal HTTP Server

```js
const http = require("http");

// 1. Define the server callback
const server = http.createServer((req, res) => {
  // Set HTTP response headers (Status 200 OK, Content-Type)
  res.writeHead(200, { "Content-Type": "text/plain" });

  // Send body data and close the response stream
  res.end("Hello from the raw Node.js HTTP server!");
});

// 2. Bind the server to port 3000
const PORT = 3000;
server.listen(PORT, () => {
  console.log(`Server is running at http://localhost:${PORT}`);
});
```

### Explanation Line-by-Line:
* `http.createServer(callback)`: Creates a server instance. The callback executes **every single time a new HTTP request reaches the server**.
* `req` (Request): Represents the incoming stream of request data.
* `res` (Response): Represents the outgoing stream used to send headers and data back.
* `res.writeHead(status, headers)`: Sets the HTTP status code and header key-value pairs.
* `res.end(...)`: Finalizes the response and transmits the payload over the TCP connection.
* `server.listen(3000)`: Starts listening for TCP connections on port 3000.

## 5. The Request–Response Lifecycle

```
[Client (Browser / Postman)]
            │  1. HTTP Request (GET /products)
            ▼
[Node.js Network Layer]
            │  2. Event: 'request' emitted
            ▼
[createServer Callback (req, res)]
            │  3. Parse req.method & req.url
            │  4. Process data / business logic
            │  5. res.writeHead(200) & res.end(data)
            ▼
[Client receives HTTP Response]
```

This entire flow is **event-driven and asynchronous**. The server never blocks while waiting for new connections.

---

## 6. Understanding the Request (`req`) Object

The `req` object gives you access to everything the client sent:

```js
const http = require("http");

const server = http.createServer((req, res) => {
  console.log("HTTP Method:", req.method); // e.g. GET, POST, PUT, DELETE
  console.log("Request URL:", req.url);     // e.g. /users, /products?category=books
  console.log("Headers:", req.headers);    // Host, User-Agent, Content-Type, etc.

  res.writeHead(200, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ message: "Request received successfully" }));
});

server.listen(3000);
```

---

## 7. Understanding the Response (`res`) Object

The `res` object is a writable stream used to craft and send the response:

### 1. Setting Status Codes & Headers:
```js
res.writeHead(200, {
  "Content-Type": "application/json",
  "X-Powered-By": "Node.js"
});
```

### 2. Writing Response Body:
```js
res.write(JSON.stringify({ status: "success", data: [] }));
```

### 3. Ending the Response:
```js
res.end(); // Must be called!
```

> **Golden Rule:** Every incoming request **must** terminate with `res.end()`. If you fail to call `res.end()`, the browser or client will spin and hang until a network timeout occurs (typically 60–120 seconds).

## 8. Manual Routing with Raw HTTP (Why Frameworks Exist)

Without a framework like Express, you must route URLs manually using conditional statements (`if` / `else` / `switch`):

```js
const http = require("http");

const server = http.createServer((req, res) => {
  const { method, url } = req;

  if (method === "GET" && url === "/") {
    res.writeHead(200, { "Content-Type": "text/plain" });
    res.end("Welcome to Home Page");
  } 
  else if (method === "GET" && url === "/api/users") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify([
      { id: 1, name: "Aditya" },
      { id: 2, name: "Pooja" }
    ]));
  } 
  else if (method === "POST" && url === "/api/users") {
    let body = "";

    // Receive incoming data chunks (since req is a readable stream!)
    req.on("data", chunk => {
      body += chunk.toString();
    });

    req.on("end", () => {
      const newUser = JSON.parse(body);
      res.writeHead(201, { "Content-Type": "application/json" });
      res.end(JSON.stringify({ message: "User created", user: newUser }));
    });
  } 
  else {
    res.writeHead(404, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ error: "Route not found" }));
  }
});

server.listen(3000, () => {
  console.log("Server listening on port 3000");
});
```

### Notice the pain points of raw HTTP:
1. Routing requires long, messy `if/else` chains.
2. Parsing request body requires manual chunk-by-chunk stream listening (`req.on('data')`).
3. Setting headers, status codes, and JSON serialization is repetitive boilerplate.
4. Handling dynamic URL parameters (e.g. `/users/:id`) requires complex custom Regular Expressions.

**Express.js was created specifically to solve these four problems.**

## 9. How Node.js Handles Thousands of Concurrent Requests

![Concurrency in Node.js](https://i.sstatic.net/awRTq.png)

![Libuv concurrency](https://media.geeksforgeeks.org/wp-content/uploads/20220208175332/resizedimagePromo2-660x371.jpeg)

Even though JavaScript executes on a **single thread**, one Node.js HTTP server can comfortably handle tens of thousands of concurrent connections:
* Network socket operations are delegated directly to the operating system kernel's non-blocking I/O multiplexer (`epoll` on Linux, `kqueue` on macOS, `IOCP` on Windows).
* When a packet arrives, the OS notifies libuv.
* The main thread simply triggers the request callback.
* No memory is wasted spawning thousands of idle operating system threads.

## 10. Common Beginner Mistakes

1. **Forgetting `res.end()`:**
   * The client spins indefinitely and eventually times out.
2. **Calling `res.write()` or `res.writeHead()` after `res.end()`:**
   * Throws `Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client`.
3. **Placing CPU-blocking synchronous code inside request handlers:**
   * Freezes the server for all other users.
4. **Not setting the `Content-Type` header:**
   * If omitted, the browser may misinterpret JSON data as plain text or trigger a file download.

---

## 11. Summary & Key Takeaways

* Node's `http` module is the foundation upon which frameworks like Express are built.
* `http.createServer()` creates a server that reacts to incoming requests via an event-driven callback.
* `req` is a readable stream of client data; `res` is a writable stream of server output.
* Every request must conclude with `res.end()`.
* Manual routing in raw HTTP becomes unmaintainable quickly, paving the way for Express.

## 12. Interview Questions

**Q1: What is the difference between `res.send()` and `res.end()`?**
*Answer:* `res.end()` is a native Node.js method from the `http` module that simply closes the response stream. `res.send()` is an Express helper that automatically sets appropriate headers (such as `Content-Type` and `Content-Length`), formats objects as JSON, and calls `res.end()` internally.

**Q2: What causes `Error: Can't set headers after they are sent`?**
*Answer:* This error occurs when server code attempts to send HTTP headers or a status code after the response has already been committed or closed (e.g. executing two `res.writeHead()` calls or forgetting a `return` statement before sending a response).

**Q3: How does the `req` object handle POST data in the raw HTTP module?**
*Answer:* In raw Node.js, `req` is a Readable Stream. Incoming POST body data arrives in chunks, which must be collected using `req.on('data', chunk => ...)` and converted to a complete string on `req.on('end', () => ...)`.
