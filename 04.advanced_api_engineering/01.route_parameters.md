# Route Parameters in Express and MongoDB

## 1. What Are Route Parameters?

In Express.js, **Route Parameters** are named URL segments used to capture dynamic values specified at their positions in the URL path. 

When you define a route with a leading colon (`:`):
```
GET /api/products/:id
```
The `:id` is a placeholder. When a client issues a request such as `GET /api/products/650c8f1e2f4a1c001f8e9b21`, Express captures that segment and automatically populates the `req.params` object:
```javascript
console.log(req.params.id); // "650c8f1e2f4a1c001f8e9b21"
```

---

## 2. Why Do We Need Route Parameters?

Without route parameters, you would have to define a hardcoded route for every single entity in your database (`/products/1`, `/products/2`, `/products/3`), which is impossible.

Route parameters allow you to:
1. Build clean, resource-oriented RESTful URL hierarchies.
2. Uniquely identify specific resources (e.g. `/users/:userId`, `/orders/:orderId`).
3. Model nested resource relationships (e.g. `/authors/:authorId/books/:bookId`).

---

## 3. Real-World Analogy

Imagine a **Post Office Box System**:
- The post office building has an address: `/post-office/boxes/`.
- Each customer rents a specific numbered box: `/post-office/boxes/:boxNumber`.
- When you tell the mail clerk *"I want the mail for box 412"*, the clerk treats `412` as the parameter, walks directly to locker 412, and retrieves your letters.

---

## 4. Core Concepts

| Term | Description | Code Example |
| :--- | :--- | :--- |
| `req.params` | An Express request object containing key-value mappings of route segment placeholders. | `const { id } = req.params;` |
| `:paramName` | Route placeholder syntax in Express router definitions. | `app.get("/users/:username", ...)` |
| `findById()` | Mongoose query method searching documents specifically by their primary key `_id`. | `await Product.findById(req.params.id)` |
| Multiple Params | Defining hierarchical nested route segments. | `/products/:category/:brand` |
| CastError | Error thrown by Mongoose when an invalid 24-character hex ID is passed to `findById()`. | Mongoose BSON casting |

### 5.3 Route: Find Single Resource by Unique ID (`GET /api/products/:id`)

```javascript
app.get("/api/products/:id", async (req, res) => {
  try {
    const { id } = req.params;

    // Validate if the ID is a valid MongoDB ObjectId format
    if (!mongoose.Types.ObjectId.isValid(id)) {
      return res.status(400).json({
        success: false,
        message: `Invalid ID format: '${id}' is not a valid 24-character hexadecimal ObjectId`
      });
    }

    const product = await Product.findById(id);

    if (!product) {
      return res.status(404).json({
        success: false,
        message: `Product with ID ${id} not found`
      });
    }

    res.status(200).json({
      success: true,
      data: product
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error fetching product",
      error: error.message
    });
  }
});
```

---

### 5.4 Route: Multiple Hierarchical Parameters (`GET /api/products/:category/:brand`)

You can define multiple placeholders in a single URL path.

```javascript
app.get("/api/products/:category/:brand", async (req, res) => {
  try {
    const { category, brand } = req.params;

    const products = await Product.find({
      category: category.toLowerCase(),
      brand: brand.toLowerCase()
    });

    res.status(200).json({
      success: true,
      count: products.length,
      data: products
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error querying products",
      error: error.message
    });
  }
});
```

## 6. Complete Runnable Server Example

Save as `server.js`:

```javascript
const express = require("express");
const mongoose = require("mongoose");

const app = express();
const PORT = 5000;

app.use(express.json());

// 1. Connect to MongoDB
mongoose
  .connect("mongodb://127.0.0.1:27017/backendClassDB")
  .then(() => console.log("MongoDB Connected Successfully"))
  .catch(err => console.error("Database connection error:", err.message));

// 2. Schema and Model
const productSchema = new mongoose.Schema({
  title: { type: String, required: true },
  price: { type: Number, required: true },
  category: { type: String, required: true },
  brand: { type: String, required: true }
});

const Product = mongoose.model("Product", productSchema);

// 3. Seed Bulk Data (for testing)
app.post("/api/products/bulk", async (req, res) => {
  try {
    const products = req.body;
    const inserted = await Product.insertMany(products);
    res.status(201).json({
      success: true,
      message: `${inserted.length} products inserted successfully`,
      data: inserted
    });
  } catch (error) {
    res.status(500).json({ success: false, error: error.message });
  }
});

// 4. Get All Products
app.get("/api/products", async (req, res) => {
  try {
    const products = await Product.find();
    res.status(200).json({
      success: true,
      count: products.length,
      data: products
    });
  } catch (error) {
    res.status(500).json({ success: false, error: error.message });
  }
});

// 5. Get Product by ID (Single Route Param)
app.get("/api/products/:id", async (req, res) => {
  try {
    const { id } = req.params;

    if (!mongoose.Types.ObjectId.isValid(id)) {
      return res.status(400).json({
        success: false,
        message: `Invalid ID format: ${id}`
      });
    }

    const product = await Product.findById(id);

    if (!product) {
      return res.status(404).json({
        success: false,
        message: "Product Not Found"
      });
    }

    res.status(200).json({ success: true, data: product });
  } catch (error) {
    res.status(500).json({ success: false, error: error.message });
  }
});

// 6. Get Products by Category and Brand (Multiple Route Params)
app.get("/api/products/filter/:category/:brand", async (req, res) => {
  try {
    const { category, brand } = req.params;
    const products = await Product.find({ category, brand });

    res.status(200).json({
      success: true,
      count: products.length,
      data: products
    });
  } catch (error) {
    res.status(500).json({ success: false, error: error.message });
  }
});

app.listen(PORT, () => {
  console.log(`Server running on http://localhost:${PORT}`);
});
```

## 8. Common Mistakes to Avoid

| Mistake | Why it fails | Correct Approach |
| :--- | :--- | :--- |
| **Not checking `ObjectId.isValid(id)`** | An invalid ID string throws an unhandled Mongoose `CastError`. | Validate with `mongoose.Types.ObjectId.isValid(id)` and return `400 Bad Request`. |
| **Returning 404 in `catch` blocks** | A server or database crash is an internal error (`500`), not a "not found" (`404`)! | Reserve `404` for when the query finishes cleanly but finds `null`. Use `500` in `catch`. |
| **Route collision with static routes** | Placing `GET /products/:id` before `GET /products/featured` causes Express to treat `"featured"` as an `:id`. | Always declare specific static routes **before** dynamic parameter routes! |
| **Assuming route params are numbers** | In Express, all values in `req.params` are **strings** by default. | Convert strings to numbers when necessary using `Number(req.params.page)`. |

## 9. Route Parameters vs. Query Parameters

```
Route Parameter:  GET /api/products/650c8...         --> req.params.id (Mandatory resource identity)
Query Parameter:  GET /api/products?category=audio   --> req.query.category (Optional filter/modifier)
```

- **Use Route Parameters** when the parameter is **essential** to pinpoint a specific resource or primary hierarchy.
- **Use Query Parameters** when the parameters are **optional**, used for filtering, pagination, sorting, or searching collections.

## 12. Interview Questions & Model Answers

### Q1: What happens if two routes match the same URL structure in Express?
**Answer:**
Express matches routes in the **exact order they are declared in the code**. If `app.get("/products/:id", ...)` is mounted before `app.get("/products/special", ...)`, Express will intercept the request for `/products/special`, assign `req.params.id = "special"`, and execute the first handler. Therefore, specific static routes must always be declared before generic dynamic route patterns.

### Q2: How does Mongoose handle querying with an invalid `_id`?
**Answer:**
MongoDB `_id` fields are 12-byte BSON `ObjectId` instances. If a string that cannot be cast into an ObjectId (such as `"123"` or `"abc"`) is passed to `Model.findById()`, Mongoose throws a `CastError: Cast to ObjectId failed for value "..."`. If not guarded by `mongoose.Types.ObjectId.isValid()` or caught properly, this results in an unhandled 500 error instead of a clean `400 Bad Request`.
