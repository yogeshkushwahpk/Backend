# API Pagination with MongoDB and Express

## 1. What is Pagination?

**Pagination** is the technique of breaking down a large dataset into smaller, manageable chunks (called "pages") before transmitting them over the network.

Instead of sending 50,000 records in a single massive HTTP response, the backend delivers data incrementally—for instance, 10 or 20 records at a time:

```
Page 1: Products 1  to 10
Page 2: Products 11 to 20
Page 3: Products 21 to 30
```

---

## 2. Why Do We Need Pagination?

Returning unpaginated database collections in production leads to severe performance degradation:
1. **Network Congestion**: Transferring megabytes of JSON data consumes client bandwidth and battery.
2. **Server Memory Exhaustion**: Loading 100,000 documents into Node.js heap memory causes high latency and V8 engine crashes.
3. **Database Performance**: Querying and serializing entire collections causes database CPU spikes and locks resources.
4. **User Experience**: Frontends cannot render thousands of DOM nodes simultaneously without browser stutter.

---

## 3. Real-World Analogy

Imagine reading a **1,000-page dictionary**:
- If someone printed the entire dictionary as a single **100-meter continuous paper roll**, finding a word or carrying it would be impossible.
- Instead, the book is divided into **numbered pages**. You flip directly to Page 45, read 20 words, and flip to Page 46 when ready.

---

## 4. The Core Pagination Formula

MongoDB provides two chainable cursor methods:
- **`limit(n)`**: Specifies the maximum number of documents to return.
- **`skip(m)`**: Specifies the number of documents to jump over before returning results.

### The Mathematical Formula:
$$\text{skip} = (\text{page} - 1) \times \text{limit}$$

| Page (`page`) | Limit (`limit`) | Calculation | Documents Skipped | Documents Returned |
| :---: | :---: | :---: | :---: | :---: |
| **1** | 10 | $(1 - 1) \times 10 = 0$ | 0 | Items 1 to 10 |
| **2** | 10 | $(2 - 1) \times 10 = 10$ | 10 | Items 11 to 20 |
| **3** | 10 | $(3 - 1) \times 10 = 20$ | 20 | Items 21 to 30 |

## 5. Implementation Guide

### 5.1 Route Implementation with Comprehensive Metadata

```javascript
app.get("/api/products", async (req, res) => {
  try {
    // 1. Extract query params and establish robust defaults
    const page = Math.max(1, parseInt(req.query.page, 10) || 1);
    const limit = Math.min(100, Math.max(1, parseInt(req.query.limit, 10) || 10));

    // 2. Calculate skip offset
    const skip = (page - 1) * limit;

    // 3. Parallel execution: fetch paginated subset and total document count
    const [products, totalDocuments] = await Promise.all([
      Product.find().skip(skip).limit(limit).sort({ createdAt: -1 }),
      Product.countDocuments()
    ]);

    // 4. Calculate pagination metadata
    const totalPages = Math.ceil(totalDocuments / limit);

    // 5. Send standardized response with 200 OK
    res.status(200).json({
      success: true,
      pagination: {
        totalDocuments,
        totalPages,
        currentPage: page,
        limit,
        hasNextPage: page < totalPages,
        hasPrevPage: page > 1
      },
      data: products
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error fetching paginated products",
      error: error.message
    });
  }
});
```

> [!IMPORTANT]
> **Status Code Correction:**
> A `GET` request fetching paginated data must **always** return **`200 OK`**. Never return `201 Created` for read operations!

## 6. Complete Runnable Server Example

Save as `server.js`:

```javascript
const express = require("express");
const mongoose = require("mongoose");

const app = express();
const PORT = 5000;

app.use(express.json());

// 1. Connect to MongoDB
mongoose
  .connect("mongodb://127.0.0.1:27017/backendClassDB")
  .then(() => console.log("MongoDB Connected Successfully"))
  .catch(err => console.error("Database connection error:", err.message));

// 2. Schema and Model
const productSchema = new mongoose.Schema({
  title: { type: String, required: true },
  price: { type: Number, required: true },
  category: { type: String, required: true },
  brand: { type: String, required: true }
});

const Product = mongoose.model("Product", productSchema);

// 3. Bulk Seed Route
app.post("/api/products/bulk", async (req, res) => {
  try {
    const inserted = await Product.insertMany(req.body);
    res.status(201).json({
      success: true,
      message: `${inserted.length} products inserted`,
      data: inserted
    });
  } catch (error) {
    res.status(500).json({ success: false, error: error.message });
  }
});

// 4. Paginated Products Route
app.get("/api/products-pagination", async (req, res) => {
  try {
    const page = Math.max(1, parseInt(req.query.page, 10) || 1);
    const limit = Math.min(100, Math.max(1, parseInt(req.query.limit, 10) || 10));

    const skip = (page - 1) * limit;

    const [products, totalDocuments] = await Promise.all([
      Product.find().skip(skip).limit(limit),
      Product.countDocuments()
    ]);

    const totalPages = Math.ceil(totalDocuments / limit);

    res.status(200).json({
      success: true,
      pagination: {
        totalDocuments,
        totalPages,
        currentPage: page,
        limit,
        hasNextPage: page < totalPages,
        hasPrevPage: page > 1
      },
      data: products
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error during pagination",
      error: error.message
    });
  }
});

app.listen(PORT, () => {
  console.log(`Server listening on http://localhost:${PORT}`);
});
```

## 8. Common Mistakes to Avoid

| Mistake | Consequence | Correct Approach |
| :--- | :--- | :--- |
| **Returning HTTP `201 Created` for GET** | Violates HTTP semantics; clients assume a resource was created. | Always use `200 OK` for GET requests. |
| **Not capping `limit`** | A user querying `?limit=100000` bypasses pagination and overwhelms the server. | Enforce a strict maximum: `Math.min(100, parsedLimit)`. |
| **Neglecting `parseInt(val, 10)`** | Query parameters are strings; `("2" - 1) * "5"` can result in unexpected type coercion or `NaN`. | Always parse query strings to integers with a radix of 10. |
| **Omitting `Promise.all`** | Running `await find()` followed by `await countDocuments()` sequentially doubles database roundtrip latency. | Execute query and count concurrently via `Promise.all([...])`. |

---

## 9. Offset Pagination vs. Keyset (Cursor) Pagination

| Feature | Offset Pagination (`skip / limit`) | Keyset / Cursor Pagination (`_id > lastId`) |
| :--- | :--- | :--- |
| **Mechanism** | Skips `n` rows using mathematical formula | Seeks directly to indexed field (`_id > cursor`) |
| **Implementation Complexity** | Very Simple; native in Mongoose | Moderate; requires tracking cursor tokens |
| **Jump to Page** | Easy: client can jump directly to page 50 | Difficult: must traverse sequentially |
| **Performance on Large Offsets** | Degrades at high pages (e.g. `skip(500000)` scans 500k rows) | Constant $O(1)$ index lookup speed |
| **Best Used For** | Admin dashboards, internal tools, standard search lists | Infinite scroll (social feeds like Twitter/Instagram) |

## 12. Interview Questions & Model Answers

### Q1: Why does `skip()` become slow on very large collections in MongoDB?
**Answer:**
Under offset pagination (`.skip(100000)`), the MongoDB query engine must still read and iterate through 100,000 index entries or documents from disk before discarding them and returning the requested `limit` records. For massive collections (millions of rows), this results in significant disk I/O and query latency. For such scale, **Keyset/Cursor-based pagination** (e.g. `.find({ _id: { $gt: lastSeenId } }).limit(limit)`) is preferred because the B-Tree index can seek directly to `lastSeenId` in $O(\log N)$ time without scanning prior records.

### Q2: What is the purpose of `Math.ceil(totalDocuments / limit)`?
**Answer:**
`Math.ceil()` rounds a floating-point number up to the nearest integer. If there are 25 documents with a limit of 10 per page, $25 / 10 = 2.5$. If you used `Math.floor()` or integer division, it would calculate 2 pages, omitting the final 5 documents. `Math.ceil(2.5)` correctly yields 3 pages, ensuring that remaining partial pages are represented.
