# API Sorting with MongoDB and Express

## 1. What is Sorting?

**Sorting** is the process of arranging API response data in a specific sequential order based on one or more document fields.

Typical sorting use cases include:
- Showing products from **cheapest to most expensive** (price ascending)
- Showing articles from **newest to oldest** (date descending)
- Showing contacts in **alphabetical order** (name ascending)

---

## 2. Why Do We Need Sorting?

Without an explicit sort instruction, database engines return documents in arbitrary, non-deterministic order (typically physical storage or insertion order). 

Adding sorting capabilities to your API provides:
1. **User Control**: Enables clients to toggle between filters like "Price: Low to High", "Highest Rated", or "Recently Added".
2. **Consistency**: Guarantees reproducible results across page reloads and paginated queries.
3. **Business Value**: Allows e-commerce stores to prioritize high-margin or top-trending products.

---

## 3. Real-World Analogy

Imagine a **deck of playing cards**:
- Unsorted, the cards are randomly scrambled.
- **Ascending Sort (`1`)**: Arranging from lowest value to highest value ($2, 3, 4, \dots, \text{King}, \text{Ace}$).
- **Descending Sort (`-1`)**: Arranging from highest value down to lowest value ($\text{Ace}, \text{King}, \dots, 3, 2$).

---

## 4. How MongoDB Sorting Works

In Mongoose, sorting is applied by chaining the `.sort()` method to any `.find()` query. The `.sort()` method accepts an object specifying the target field and the sort direction:

```javascript
// Ascending Order (Smallest first: 1 -> 10, A -> Z, Oldest -> Newest)
Product.find().sort({ price: 1 });

// Descending Order (Largest first: 10 -> 1, Z -> A, Newest -> Oldest)
Product.find().sort({ price: -1 });
```

### Direction Values Reference

| Value | Direction | Effect |
| :---: | :--- | :--- |
| **`1`** | **Ascending (`asc`)** | Smallest to largest: numbers increase ($1 \to 100$), letters $A \to Z$, dates past $\to$ future. |
| **`-1`** | **Descending (`desc`)** | Largest to smallest: numbers decrease ($100 \to 1$), letters $Z \to A$, dates future $\to$ past. |

## 5. Dynamic Sorting Implementation Patterns

### Pattern 1: Single Field Sort via Query Parameter (`?sort=asc|desc`)

```javascript
app.get("/api/products/sorted", async (req, res) => {
  try {
    const { price } = req.query;

    const sortCriteria = {};

    if (price === "asc") {
      sortCriteria.price = 1;
    } else if (price === "desc") {
      sortCriteria.price = -1;
    }

    const products = await Product.find().sort(sortCriteria);

    res.status(200).json({
      success: true,
      count: products.length,
      appliedSort: sortCriteria,
      data: products
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error executing sorted query",
      error: error.message
    });
  }
});
```

---

### Pattern 2: Flexible Multi-Field Sort String (`?sortBy=price:desc,createdAt:asc`)

In modern production APIs, clients can specify any field and direction using a delimited string format:

```javascript
app.get("/api/products", async (req, res) => {
  try {
    // Expected format: ?sortBy=price:desc or ?sortBy=title:asc
    const { sortBy } = req.query;
    const sortCriteria = {};

    if (sortBy) {
      // Split "price:desc" into ["price", "desc"]
      const [field, direction] = sortBy.split(":");
      sortCriteria[field] = direction === "desc" ? -1 : 1;
    } else {
      // Default: Newest first
      sortCriteria.createdAt = -1;
    }

    const products = await Product.find().sort(sortCriteria);

    res.status(200).json({
      success: true,
      appliedSort: sortCriteria,
      count: products.length,
      data: products
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error during sorting",
      error: error.message
    });
  }
});
```

## 6. Complete Runnable Server Example

Save as `server.js`:

```javascript
const express = require("express");
const mongoose = require("mongoose");

const app = express();
const PORT = 5000;

app.use(express.json());

// 1. Connect to MongoDB
mongoose
  .connect("mongodb://127.0.0.1:27017/backendClassDB")
  .then(() => console.log("MongoDB Connected Successfully"))
  .catch(err => console.error("Database connection error:", err.message));

// 2. Schema and Model
const productSchema = new mongoose.Schema(
  {
    title: { type: String, required: true },
    price: { type: Number, required: true },
    category: { type: String, required: true },
    brand: { type: String, required: true }
  },
  { timestamps: true }
);

const Product = mongoose.model("Product", productSchema);

// 3. Bulk Seed Route
app.post("/api/products/bulk", async (req, res) => {
  try {
    const inserted = await Product.insertMany(req.body);
    res.status(201).json({
      success: true,
      message: `${inserted.length} products inserted`,
      data: inserted
    });
  } catch (error) {
    res.status(500).json({ success: false, error: error.message });
  }
});

// 4. Sorted Products Route
app.get("/api/products/sort", async (req, res) => {
  try {
    const { price, sortBy } = req.query;
    const sortOptions = {};

    if (price === "asc") {
      sortOptions.price = 1;
    } else if (price === "desc") {
      sortOptions.price = -1;
    } else if (sortBy) {
      const [field, dir] = sortBy.split(":");
      sortOptions[field] = dir === "desc" ? -1 : 1;
    } else {
      // Default: Sort by newest created
      sortOptions.createdAt = -1;
    }

    const products = await Product.find().sort(sortOptions);

    res.status(200).json({
      success: true,
      appliedSort: sortOptions,
      count: products.length,
      data: products
    });
  } catch (error) {
    res.status(500).json({
      success: false,
      message: "Server error executing sorted query",
      error: error.message
    });
  }
});

app.listen(PORT, () => {
  console.log(`Server listening on http://localhost:${PORT}`);
});
```

## 8. Common Mistakes to Avoid

| Mistake | Consequence | Correct Approach |
| :--- | :--- | :--- |
| **Returning HTTP `201 Created`** | `GET` requests returning sorted results should never use `201`. | Always return `200 OK` for data reads. |
| **Unindexed sorting on large collections** | In-memory sorting of 100,000+ unindexed documents triggers MongoDB's 32MB RAM sorting limit error (`Executor error: Overflow sort`). | Create an index on frequently sorted fields: `productSchema.index({ price: 1 })`. |
| **Allowing arbitrary sort fields from users** | Passing unvalidated client strings into `.sort()` can expose internal fields or cause crashes. | Whitelist permissible sort fields before querying: `const allowed = ["price", "createdAt", "title"]`. |
| **Ignoring secondary tie-breaker fields** | If 5 products have the identical price, their order between page loads may fluctuate. | Provide a stable secondary sort key: `.sort({ price: 1, _id: 1 })`. |

## 9. Combining Sorting with Pagination and Filtering

Sorting should always be chained alongside filters and pagination in this precise order:

```javascript
const products = await Product.find(filter)
  .sort(sortCriteria)   // 1. Sort the full matching dataset
  .skip(skip)           // 2. Skip to current page offset
  .limit(limitNumber);  // 3. Restrict to page size
```

> [!NOTE]
> MongoDB applies sorting **before** `skip` and `limit`, guaranteeing that pagination operates on an already ordered result set.

## 12. Interview Questions & Model Answers

### Q1: Why is indexing critical for fields used in `.sort()` operations?
**Answer:**
When MongoDB sorts a query using an indexed field, it traverses the pre-ordered B-Tree index structure in $O(\log N)$ time and streams matching documents in order. If the sort field is **unindexed**, MongoDB must load all candidate documents into server RAM and perform an in-memory sort. If the memory consumed by this in-memory sort exceeds **32 Megabytes**, MongoDB aborts execution and throws an `Executor error: Overflow sort stage buffered data exceeded memory limit`.

### Q2: How does compound sorting work in Mongoose?
**Answer:**
Compound sorting arranges data sequentially across multiple keys. By passing an object with multiple keys (e.g. `.sort({ department: 1, salary: -1 })`), MongoDB first groups and sorts documents alphabetically by `department` ascending. Within each department, it breaks ties and orders documents by `salary` descending.
